# Environment facts — hosts, templates, vmids

Pipeline/host behavior that holds on any node. **Estate-specific ground truth — which hosts exist, their endpoints and node names, datastores, template vmids, token locations, and what is live right now — lives in `infrastructure-status.md` at the repo root (gitignored, local only).** Read it before touching a host; it wins over anything here or in tracked docs. Re-verify anything vmid/space-related before relying on it; it moves.

## Hosts

The estate has more than one Proxmox host on different endpoints, API tokens and datastores; they are not interchangeable, and at least one is routinely shared with non-range VMs (per-host details and the dashboard address: `infrastructure-status.md`). From the dev host only the Proxmox API port (:8006) and the guest-agent channel are reachable — other VM ports TCP-RST. **Ping is not a liveness signal** (a tailnet bridge can answer ICMP while forwarding nothing): probe `curl -k https://<node>:8006/` for any HTTP code, not `000`. State, snapshots and disks survive a node outage; resume with `--from-phase`.

## Templates

Cloud-init capability is what makes a template usable; which vmid carries which base image is `infrastructure-status.md`, the build procedure is [usage-people.md](usage-people.md#templates).

- **`base-fedora44` ships without cloud-init** — use the `-fix` variant where one exists. Fedora also needs SSH password-auth forced via a `00-*` drop-in, `named` bound beyond `127.0.0.1`, and `httpd` with `ServerName localhost` — folded into `fix_services_on_boxes` (`guests/service_fixup_ops.py`).
- **Alpine needs persistent `ssh_pwauth` and a `%wheel` rule in the main sudoers file**: the image ships both absent, so a NOPASSWD entry living only in `sudoers.d` vanishes if a `writable-sudoers` plant makes that dir 0777.
- **Fedora + the guest agent is confined** (SELinux `virt_qemu_ga_t`): `dnf`/`rpm`/`systemctl` denied, `setenforce 0` denied; SSH as the cloud user lands `unconfined_t` with real root — the working path. Golden builds set `SELINUX=permissive` on Fedora goldens before sealing (`set_fedora_selinux_permissive`); a base template that still enforces is fine. Verify `getenforce` on a clone after any template rebuild.
- **Windows** ships all firewall profiles disabled, so firewall-rule effects do nothing until `Set-NetFirewallProfile -All -Enabled True` (`common/windows_ops.py` does this, plus enabling `RemoteDesktop-UserMode-In-TCP/UDP` — the DC template ships that group disabled too). A Windows clone's guest agent takes ~8 min to appear.
- **red01 is cloned from a fixed Ubuntu template** (`DEFAULT_TEMPLATE` in `red/red01_ops.py` hardcodes the name), linked clone then reconfigured — no per-competition red template.

## vmid occupancy

- **Default team identifiers (101+) collide on shared hosts.** Pass `TEZ_TEAM_IDENTIFIERS` (or `--team-identifiers`) explicitly on any host that is not empty; occupied blocks per host: `infrastructure-status.md`.
- **red01's slot is reserved per competition, never a shared default** ([architecture.md § Network and isolation](architecture.md#network-and-isolation)): vmid from Compfile `red01_vmid`, else the placement's recorded one, else derived one golden stride past this placement's last band (`red/red01_ops.default_red_vmid`); IP from Compfile `red01_ip`, else recorded, else selected at deploy from `infra/collisions.RED01_IP_BAND` — the lowest address nothing answers and this placement does not already claim (legacy defaults excluded). The vmid is preflight-gated: an occupied slot is a refusal naming the owner; an address a running guest answers is refused, and an unverifiable one is refused unless the Compfile or a placement record already carries it (a slot with no IP yet is selected at deploy, after preflight). `check_placement` and a slot-band property test enforce the math, so concurrent comps need no hand-spaced scoring vmids to keep red01 clear.
- **Engine management IPs are shared across concurrent deploys unless separated**: `clean_engine_for_template` SSHes to the *planned* mgmt IP, so a collision can land cleanup on a live foreign engine's `.env`/`event.conf`/host keys. Give each concurrent comp its own `TEZ_ENGINE_MGMT_IP`; the preflight scans cluster-wide and refuses the default address when any guest on it is unverifiable.
- **Reclaim orphaned ranges with `destroy-competition.py` from the matching comp dir**, never an ad-hoc sweep. Occupancy is not tracked in docs — check the Proxmox API on the target host before a deploy.

## Headscale

External headscale instance the pipeline administers over ssh+sudo (`TEZ_HEADSCALE_*` in the deploy env; host and credentials: `infrastructure-status.md`; [remote-access.md](remote-access.md)). Notes below are host-agnostic; the policy is regenerated by `net/remote_access_ops.py`.

- Runtime `headscale/headscale` (v0.29.x) container with an sqlite DB; `docker` is root-only, so every CLI call is `sudo docker exec headscale headscale …`. Embedded DERP on. MagicDNS on, base domain `<tailnet-base-domain>` (live value: `infrastructure-status.md`).
- **Policy**: `policy.mode: file`; the pipeline regenerates the whole policy from `tezcatlipoca-remote-access.json` beside it; pre-existing nodes are untagged and keep access via `group:full-access`.
- **v0.29 CLI**: no `routes` command (approvals ride the policy's `autoApprovers`; list with `nodes list-routes`); version-2 policy group/grant sources need `@`-suffixed usernames (a bare name parses as a host reference); `policy check` wants `--file`; `users destroy -n <name> --force` refuses while the user owns nodes.
- **Tag-sourced grants do not reach routers' packet filters** — a tag-sourced dial black-holes at the router even though the node's own routes are filtered correctly; user/group sources work. tezcatlipoca keys participant grants on usernames, not tags ([remote-access.md](remote-access.md)). Upstream-worthy defect.
- The VPS is itself a tailnet node and runs the mgmt-LAN subnet router; probe service ports, never ping (the ICMP-without-forwarding trap again).

## Node runtime behavior

- **A shared host's RAM is the binding constraint for satellite-heavy Windows ranges** — check the live margin (`infrastructure-status.md` or the API) before placing several Windows-heavy teams.
- **The management network is one flat L2 across hosts**: `TEZ_ENGINE_MGMT_IP` and the satellites' `nodes.json` `jump_mgmt_ip` are contested cluster-wide, not per host — the defaults (`common/constants.py`) are whatever every competition gets unless set otherwise. A fresh deploy auto-selects the lowest free address in `ENGINE_MGMT_BAND` **only when every running guest's agent answers**; with any unverifiable guest it keeps the default and the preflight refuses, naming the guests. **Set an explicit, checked `TEZ_ENGINE_MGMT_IP`** on a busy estate, or make the agent-less co-tenants verifiable first. Band override: `engine.mgmt_ip_band = "START-END"`.
- **netplan refuses world-readable configs** — the engine's team-NIC netplan files are mode `0600`.
- **Docker re-syncs iptables on every container start/restart** (`FORWARD` → DROP, team rules wiped); `range-firewall.timer`/`range-healthcheck.timer` and `ensure_nat_forwarding` cover this, and the red segment's rules have their own `range-red-firewall.timer` ([architecture.md](architecture.md#network-and-isolation)).
- **Quotient crash-loops without `event.conf`**, so it's pushed before nakon runs.
- **New VirtIO NICs need a cold boot** — a guest-level reboot doesn't trigger the PCI scan.
- **Fresh clones can boot with an empty `/etc/resolv.conf`** (cloud-init ignores `dns.servers` on a static IP), so `fix_dns_on_boxes` runs in the deploy. Never point boxes at their own team's `dns*` box at clone time — deadlock (its bind9 needs a working resolver to install via apt).
- **Stale ifupdown2 state breaks `ifreload -a` node-wide**: `/run/network/ifstatenew` can carry dead bridges from gone comps, failing every API-driven network change on a missing `/sys/class/net/vmbrNNN/brif/` (invisible via the API). Repair: `rm /run/network/ifstatenew && ifreload -a`. Tear team bridges down with `ifdown`, never raw `ip link del` (which creates this state).
- **Quotient secrets are plaintext-but-0600** on the engine (`/opt/quotient/.env`), generated fresh per deploy. Box/credlist usernames are themeable and not secret; passwords always are.
